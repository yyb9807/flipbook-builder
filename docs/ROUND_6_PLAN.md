# 第六轮计划：撤销与页面版本恢复

制定于 2026-10-19，实施前基线为 `e80a6b0`。本轮围绕作者误改后的恢复，沿用当前编辑器、React/FastAPI/Postgres/DBOS 和单共享实例边界。

## 产品与交互

1. 未保存的页面草稿提供「撤回本次修改」，仅清除当前页草稿，保留其他页面草稿；输入框原生撤销继续有效。
2. 内容检查器加入「历史版本」，展示已保存时间、更改类型和内容概览。选择版本只读预览，恢复前可看到实际合并后的页面。
3. 提供上一版本入口以撤销最近一次保存（实施收尾将入口命名为「预览上一版本」，先展示结果再确认恢复）；恢复自身也保存为新版本，因此能从历史找回恢复前内容。恢复统一需要重新人工核对，不代表资料真实性认证。
4. 历史恢复仅作用于当前页内容、资料和热点。现有子页、父子关系和当前有效连接必须保留；旧版没有的已连接区块会保留到恢复结果中。不能将历史版本当作整棵作品树的时间旅行。
5. 活动生成、待保存请求或任意页面草稿存在时暂不恢复，显示原因；跨标签并发修改返回冲突，保留预览与草稿，重新读取后由作者选择。手机从内容面板进入历史，沿用四项底部工具。

## 数据与实现

- Postgres增加项目修订号、页面版本表和恢复操作幂等记录。编辑与生成的内容提交在同一业务事务留存版本；旧项目在首次变更时补当前基线。版本按公开内容白名单保存，不存凭据、供应商连接、工作流状态、原始输入或整棵树。
- 已保存正文/资料/热点文本与几何变化生成版本；纯选择不制造正文版本。恢复是一次新的原子写入，校验作品/页面归属、预期项目修订号、活动任务和图片资产。修订冲突不会自动重试覆盖。
- 正常编辑请求增加可选的预期修订号以兼容旧客户端；新编辑器携带该号，服务端返回确认修订。版本列表、详情和恢复API在页面范围内工作。
- 恢复合并历史内容与当前真实连接。不得删除子页、改变连接目标、恢复任务状态或重新调用模型；保留的区块若使上限超过12，明确拒绝整次恢复。恢复后核对状态重置。
- 本地作品的内容与版本在同一浏览器存储条目中提交，每页保留最近50个版本；存储失败不丢弃旧内容或草稿。本地没有替换背景图片的编辑操作，历史不重复保存图片二进制，继续使用当前图片。服务器版本保存在Postgres，不主动裁剪。
- 历史不进入公开JSON、ZIP或阅读界面。删除作品仍会删除其历史；版本不替代数据库与图片备份。

## 验收

- 后端真实Postgres：知识/图片编辑、来源核对、旧项目baseline、连接生成留版、恢复幂等、陈旧修订、事务失败、活动任务、归属边界、历史字段白名单与保留分支。
- 前端：草稿撤回范围、本地原子历史和存储失败、恢复前预览、撤销与找回、刷新持久化、保存/恢复排队与跨workspace迟到响应、冲突不覆盖。
- 全量前后端测试、lint、类型/production构建、双环境离线播放器、7项进程恢复和19项整栈HTTP回归。
- 实际浏览器桌面与390px手机：手动作品编辑/保存/分支/恢复/刷新/预览/导出；服务器生成知识页、修改并恢复、已有两层分支保持可导航；图片热点恢复；中英、草稿与冲突提示。模型调用使用受控本地供应商，不产生付费请求。

## 明确边界

本轮不增加多人协作、账号、独立只读发布、全项目删除撤销、通用跨版本任务迁移或真实模型质量评估。桌面与手机视觉验收采用一次成批检查、一次修复确认；功能失败继续修复并验证受影响路径。
