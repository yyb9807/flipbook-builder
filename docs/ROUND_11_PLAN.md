# 第十一轮计划：来源检索、引用关联与创作工作台优化

制定于 2026-10-19，实施前基线 `d828868679305ed308315554d1f056aff4188bed`，分支 `codex/source-citations-workspace`。按用户授权先计划后实施，遇到常规问题自主解决；不预置、下载或接入具体模型，不新增账号、向量库或检索模型。

## 审查结论与实施顺序

现有参考资料是页级作者填写信息，区块没有关联字段；页面历史和固定发布采用字段白名单，直接添加字段会在恢复或导出时丢失。当前 URL 校验仅适合外链，不能作为任意网页抓取的 SSRF 防线。界面把正文与最多 12 条参考资料放入窄长表单，画布显示已保存内容而表单显示草稿；手机的工作区与检查器标签也不一致。

先建立来源与关联数据合约、公共接口和保存/恢复/发布规则，再接入来源面板及阅读器，随后统一首页、编辑器、设置和阅读界面的层级、间距与响应式行为，最后做自动化、真实公共接口、正式整栈和实际浏览器验收。已有模型质量开发集与保留集原样保留，当前生成实验仍默认关闭。

## 来源检索与信任边界

本轮提供 Wikipedia 中英文公共检索和页面摘录，保留手工资料入口。使用 MediaWiki 原生 REST `search/page` 与单响应 `page/{title}/with_html` 获取标题、页面版本、许可和正文，记录固定版本链接；用户明确提交查询或选择候选后才访问公共服务，不随键入发送请求，不要求模型 Key。官方协议与访问约定见 [REST API](https://www.mediawiki.org/wiki/API:REST_API/Reference/en) 和 [Access policy](https://www.mediawiki.org/wiki/Wikimedia_APIs/Access_policy)。审查时本机中英文检索与页面读取均 HTTP 200；实际连通不替代模拟异常测试。

后端仅构造固定的 `zh.wikipedia.org` / `en.wikipedia.org` HTTPS 请求，语言枚举、标题完整编码；不接收任意抓取 URL、来源服务地址或请求级凭证。不跟随重定向，不访问 HTML 中的链接/图片；流式限制响应体积、超时、并发与短期缓存，尊重上游限流。HTML 只在后端转纯文本，不进入作品 DOM。候选标题、摘要和来源摘录始终按文本渲染。

接口为 `GET /api/sources/search?q=...&language=zh|en` 和 `GET /api/sources/page?key=...&language=zh|en`，只读且不写项目。检索结果、全文获取失败、无结果、429 和超时各有明确状态；失败保留查询和已编辑资料，仍可手填。返回摘录控制在 3000 字符，可能截断并明确说明，不假装保存整页网页。

## 引用数据与保存

沿用现有 `content_metadata` v1 的页级 `references`，每页最多 12 条，保留旧字段。新增可选公开字段：`excerpt`、`locator`、`source_revision`、`retrieved_at`、`source_provider`、`source_language`、`license_title`、`license_url` 及摘录版本摘要。允许作者校正，定义为“作者保存的来源摘录”，不是不可伪造的系统取证记录；摘要只用于辨认保存副本，不代表事实可信度。没有摘录的旧资料保持兼容。

每个正文区块新增可选 `reference_ids`，最多 6 个，必须对应同页稳定资料 ID，不把 `[1]` 编号写进正文。编号由资料列表顺序派生；没有正文区块的图片页继续支持页级来源。关联表示作者指向依据，不自动判断该来源支持具体结论，不做自动逐句引用或人工核对。

内容与来源共用一份页面草稿，并通过既有带 `expected_revision` 的 PATCH 原子保存。正文、来源、引用关系变化均清除旧核对，保留显式作者声明的既有规则。删除被引用的资料前必须解除关联；删除区块清除其关联，页级资料保留。添加子页不把父页资料自动声明为子页依据。

页面历史保存摘录和关联，恢复预览与实际恢复一致。为保护较新分支而保留的当前区块，也必须保留所需当前来源；若同 ID 存在不同来源内容，安全地重命名并重写关联，或在无法无损合并/超限时原子拒绝。不能悬空或悄悄绑定错误版本。固定发布、JSON、前后端 ZIP 和共享播放器都保留允许的资料与关联；阅读使用本地保存的摘录，外链为可选入口，后续编辑与断网/停库不改变旧快照。

## UX/UI 方向与范围

模式为 Operate（创作）和 Read（阅读），服务内容创作者、教师与知识整理者；延续纸白、海绿、墨色、系统中文字体与扁平工具界面。普通室内桌面编辑和移动阅读需要清楚对比、可见焦点与低干扰状态。此次属于既有设计体系内的整体流程与布局优化，按用户授权直接决定实施，不增加设计确认环节或替换品牌。

- 编辑检查器统一为“内容 / 来源 / 分支（或热点）/ 历史”。来源独立面板，选定区块后可检索、预览摘录、加入资料并关联，也可手填、解除关联和核对。持续显示当前页、草稿与保存操作，切面板不提交或丢稿。
- 桌面适度加宽检查器，画布保持可读宽度；草稿与已保存预览明确区分。手机底部收为“画布 / 页面 / 编辑”，编辑区域使用同一四标签，配合安全区、可滚动长内容和触控尺寸。
- 首页突出无模型的手动创作与继续编辑，示例作为辅助入口；作品库补充最近更新、存储位置、筛选和空结果。设置统一工作台的表单与导航节奏，不新增具体模型推荐。
- 阅读器区块后显示引用编号，可键盘定位页末资料并返回对应区块。页末优先展示资料、保存摘录、版本与许可，生成说明渐进展开，减少重复空信息。统一编辑、在线阅读、离线与固定发布表现。
- 保留中英文、错误/处理中/空结果、减少动态偏好、可见焦点和长标题布局；不引入装饰动效、外网字体或营销式页面结构。

## 验收与证据

1. 旧资料兼容、字段限制、引用去重/悬空拒绝、草稿与跨页迟到请求隔离；恶意 HTML/URL、上游错误、超限/超时/429、缓存和固定域名请求测试。
2. 隔离 Postgres 全套：原子保存、核对重置、并发冲突、历史内容与保留分支来源合并、固定发布与导出不丢字段。真实进程验证生成恢复、历史和发布，模型请求仅本地受控供应商。
3. 前端测试、lint、双环境离线播放器、构建；正式 Compose 四服务构建与 HTTP 验收；旧开发/保留样例完整性继续核对。
4. 实际浏览器无模型完成创建/编辑 → 真实公共检索 → 读取摘录 → 关联两个区块 → 保存 → 引用跳转/返回 → 编辑 → 历史恢复保护分支 → ZIP 下载 → 固定发布 → 原稿修改快照不变 → 停编辑/供应商/数据库后的独立引用阅读。异常用受控接口补齐，真实公共内容和受控内容分别标记，不冒充模型输出。
5. UI 在实施后集中检查桌面与 390px 中文/英文，批量修复后最多再确认一轮；运行一次设计检测并做独立完成审查。保存最终截图、非敏感机器证据、范围限制，更新产品/架构/设计与操作文档。不新增 GitHub Actions，不自动 commit/push。

## 实施决策附注

- 恢复历史时选择同 ID 不同副本直接原子拒绝（409），不自动改名，以便作者明确处理版本冲突；前后端策略一致。
- 浏览器验收分为两条：本地免模型作品用于真实公共来源、编辑、引用和 ZIP；服务器上的原创受控样例用于历史保护、固定发布和停库独立阅读。此次不新增本地作品上传到服务器发布的功能。
- 当前应用内浏览器不允许 `file://`，实际 ZIP 已下载并检查，但实际浏览器打开解压文件未执行；双环境 JSDOM 运行编译播放器的结果单独记录，不替代跨浏览器验收。
