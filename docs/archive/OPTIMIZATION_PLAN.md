## 1. 业务方向

产品定位为「免账号、自托管、可校正、可离线发布的视觉知识工作台」。首要使用情境是把一幅图或一个主题制作成具有分支解释的作品，而后分享给读者。暂以教师、内容创作者与知识整理者为目标人群假设，未来用实际反馈验证。

核心价值顺序：内容能理解 → 热点位置准确 → 内容可修改 → 过程可恢复 → 作品可独立阅读。首页应展示真实可操作作品，避免把模型配置当成产品第一步。

## 2. 业务流程与信息架构

主流程：体验示例 → 选择图片/主题 → 创建 → 检查内容与热点 → 扩展分支 → 预览 → 导出。

| 页面 | 主要任务 | 关键状态 |
|---|---|---|
| 工作台 | 开始创作、继续作品、体验示例 | 首次访问、无后端、无 Key、已有作品、输入草稿、创建失败 |
| 编辑器 | 检查页面、调整热点、选择探索方向、扩展分支 | 无图片、已完成、正在生成、无选择、部分成功、保存失败 |
| 作品预览 | 阅读、点击分支、返回、看当前位置 | 初始页、子页、末页、缺失资产、窄屏 |
| 模型设置 | 配置服务、测试、选择是否记住 Key、清除 Key | 未保存草稿、测试中、测试成功/失败、临时/持久凭据 |
| 关于/帮助 | 理解定位、部署边界、创作方式 | 中英文 |

保留现有路由兼容；本轮不以更换 URL 为前提。共享浏览使用独立只读状态，不能覆盖作者正在编辑的项目。

### 创建

- 主题文字与关键词草稿跨设置页保留；文件对象仅保留当前会话，刷新后解释需要重新选择，不写入 localStorage。
- 未配置 Key 仍可打开示例、查看已有作品、显式创建示例副本后编辑、预览和导出；浏览示例不自动向作品库添加项目。
- AI 操作入口就地说明需要配置的服务，避免全页重复警告。
- 失败保留用户输入。根页分析、子页生成和单页再生均支持查询与恢复，浏览器连接不作为任务身份；空根页也显示独立任务面板。应答丢失时先找原操作，图片仅在尚未确认接收时要求重新选择并核对原文件。

### 编辑

- 画布是主区域；左侧页面结构，右侧热点/内容检查器。
- 平板与手机改为「页面 / 画布 / 分支或热点 / 内容」可切换工作区，不把三列压到屏幕外；当前页与保存入口持续可见。
- 热点可键盘聚焦和移动；拖动过程中仅本地预览，结束时保存一次；Escape 取消尚未提交的移动，保存失败提供重试和本地恢复副本。
- 页面草稿按项目/页面保存在浏览器，跨面板、设置、页面切换和刷新保留；顶部保存入口与全局草稿状态一致，保存后才预览/导出。
- 页面文字、布局与热点逐步进入结构化 SceneDocument，旧图片节点继续可读。
- 本地区块无需任意改稿即可直接添加子页；点选即定位对应字段，分支的打开与添加有独立动作。新浏览器重新打开服务器作品时也能读到最近一次失败/部分完成说明。

### 阅读与发布

- 图片完整显示，热点使用同一图像坐标系，说明文字保留为可访问 DOM。
- 结构化知识页与图片场景共用 SceneRenderer；预览和离线播放器复用。
- 公开作品只含内容与资产，不携带 Key、编辑 API 配置或用户草稿。
- 离线包目标支持 file://；安全编码数据，防止脚本注入。本轮已验证文件环境中的播放器启动和导航，但真实浏览器双击打开被浏览器工具的协议策略阻止，尚未完成该项验收。

## 3. 生成与数据架构

两条生成流程：

1. 知识页：同一次模型调用生成标题/导读/解释区块 → 严格内容合约 → AI插图（明确可选）→ 确定版式与无图像坐标的区块连接。文字可改，结构可校验，来源说明与作者资料独立保存。
2. 图片场景：上传图/参考编辑 → 对真实图像定位 → 人工校正。定位失败不能伪造置信度或固定网格结果。

现有 React、FastAPI、Postgres 和节点关系继续使用。新增结构化页面采用可选字段/版本化适配，先验证一条流程，保持旧数据兼容。

三种任务均使用稳定 ID、状态查询、SSE 事件补发和显式取消。独立 DBOS PoC 与子页17场景先建立基线；第三轮扩展根页和再生后，共36个真实进程场景分次通过。再生成功前保留原内容，失败/取消不覆盖；未知调用与资产丢失同时发生时保持收费确认保护，核实并取消后才解锁。

## 4. 视觉和交互方向

总体为内容优先的编辑工作台：浅色矿物白背景、深墨色文字、克制的海绿色强调、清楚分割与对齐。作品内容可以丰富，界面本身保持安静。最终 tokens 和组件规则记录在 DESIGN.md。

- 排版以系统中文无衬线为主，适度字号层级；不用依赖外网字体。
- 圆角分三档，阴影仅用于浮层；状态色有语义，不用装饰渐变或弹跳热点。
- 按钮分主要、次要、危险；图标按钮有可读名称，焦点可见。
- 动效仅用于状态、空间变化和操作反馈，尊重 reduced-motion。
- 首页是可操作工作台，示例直接证明产品机制，不引入虚构客户、指标和营销长页。

## 6. 验证策略

- 自动化覆盖有实际风险的行为：密钥不泄漏、假图片拒绝、HTML 安全、归属检查、焦点与确认行为、坐标/拖动保存、示例隔离和导出。
- 桌面与移动界面做一轮批量检查，集中修复后再确认一轮，避免无休止微调。
- 有后端/数据库时做完整服务验证；缺少基础设施时准确列明未验证边界，使用本地示例验证产品主流程。
- 保留审核与研究文档，新增实施记录反映实际变化、测试结果和后续决策。

## 7. 持续优化规则
