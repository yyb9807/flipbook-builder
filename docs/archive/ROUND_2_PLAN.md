## 阶段一：现有真实整栈

启动现有 Docker Desktop，使用独立 Compose project、数据库卷、端口和上传目录，避免改写已有实例。运行全量 Postgres 测试、重复应用 schema、前后端容器构建；从 nginx 入口验证页面、健康检查、项目 CRUD、实际图片上传、内容编辑和导出。生成接口用受控服务替身验证，避免使用真实付费凭据。修复实证问题并记录精确结果后，再修改生产任务流程。

**阶段一已通过**：真实 Postgres 16.15、Python 3.13.16/FastAPI、正式前端/nginx 构建运行；后端 145 项测试与 nginx HTTP 15 项检查通过，容器重启后 JSONB 内容仍在。已修复陈旧的 413 断言和固定容器名影响隔离部署的问题。详见 [Postgres 整栈证据](POSTGRES_STACK_VERIFICATION.md)。收到该通过结果后才启动阶段二生产源代码实施。

## 阶段二：持久子页生成

先将「选中热点生成子页」迁移为持久任务。上传分析与单页重新生成保持兼容，本轮不同时改造全部流水线。

任务提交返回稳定 ID，重复操作 ID 不重复生成；公开状态与事件保存在 Postgres，浏览器断线只结束订阅，不取消任务。步骤产物可重用，子页提交幂等且保留部分成功。临时 Key 只进入内存，重启后明确等待重新提供。远端成功而本地结果未知的窗口进入待确认，显式重试才允许再次调用。取消持久化，防止晚到结果覆盖取消状态。

前端保存非秘密任务引用，重载后查询/订阅当前任务；提供等待凭据、结果待确认、部分失败、完成和取消状态，以及对应恢复操作。保持既有草稿保护、坐标规则、页面保存与生成互斥。

具体执行契约依据 DBOS 当前 API、本地 PoC 和真实 Postgres 行为确定，实施后更新记录，未验证能力不写为完成。

具体契约见[持久子页生成设计](DURABLE_INTEGRATION_PLAN.md)。已选择单个异步工作流顺序处理热点，规划/出图/定位/提交分别 checkpoint；任务和执行器入队同一个 Postgres 事务，取消和子页提交遵循同一锁顺序。**阶段二已实现并验收**：真实PG后端162项、前端136项、真实进程17场景通过；独立审查4个P2已修复复验。浏览器实测刷新找回，完整按钮流程受工具超时限制，详见[本轮实施记录](ROUND_2_IMPLEMENTATION.md)。

## 验收

- 原有全量数据库测试与新增 API/事务回归通过；容器整栈可从单一入口使用。
- 真实服务进程 SIGKILL 后重启恢复；已完成步骤不重复调用，已提交子页不重复创建。
- SSE 断连/重连和事件游标可恢复；显式取消有效，刷新不触发取消。
- 缺少临时 Key 时等待，明确提供后继续；数据库、日志、事件与执行器序列化中不存在测试秘密，包含负控扫描。
- 结果未知不会自动重复付费请求；用户可明确确认重试或取消。
- 前端 build/lint/test、后端完整测试、独立代码复核，以及实际浏览器恢复操作检查通过。

进度与最终证据分别记录到 `POSTGRES_STACK_VERIFICATION.md` 和本轮实施报告。
