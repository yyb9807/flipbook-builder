## 已完成的实际流程

「选择热点 → 创建持久任务 → 规划 → 出图 → 定位 → 逐页提交」已接入正式 API 和前端。浏览器负责读取任务状态，刷新、进入设置、切换作品或断开 SSE 不会取消服务器任务；明确点击取消才写入取消意图。

每个热点按顺序执行，规划、出图、定位、提交分别有 DBOS 检查点。Postgres 保存冻结输入、稳定节点 ID、远端调用意图、成果与事件。已有成果在重放时复用；取消与子页提交用同一锁顺序，晚到远端结果不会在取消后发布页面。

- **原子提交**：业务 job、父页生成状态、首事件与 DBOS 入队位于同一 Postgres 事务，回滚不留孤儿任务。确认决策与无秘密通知也同事务写入。
- **操作幂等**：初次请求前，浏览器保存 operation ID、原关键词与模型元数据。应答丢失后精确查询同一操作，重复提交复用原 job；旧 SSE 的稳定 `x-operation-id` 重放也可重新订阅。
- **临时凭据**：Key 只进入进程内 vault，30 分钟过期、容量100，终态与取消清理。重启或过期后，尚需调用的阶段进入 `waiting_credentials`，必须明确提供与原服务地址/模型匹配的凭据。查询、事件、retry、accept、cancel 不带 Key。
- **收费边界**：持久流程关闭应用、SDK 与 Flux 参数降级的隐式重试。结果未知进入 `waiting_confirmation`，不会自行再次调用；明确 retry 才允许新尝试，accept 可以保留已完成文字或图片，cancel 保留已提交子页。
- **本地故障**：数据库短暂连接/事务错误只重试本地操作，不重发供应商请求；已返回的远端成果留在内存重写，进程若同时丢失则由持久 intent 保守转待确认。
- **执行器约束**：单 worker、单副本，专用 Postgres advisory lock 防止同库双执行器。锁丢失时旧进程退出。受支持的 Docker/本地启动配置5秒有界 graceful wait，避免 SSE 长订阅挡住停机与恢复。

极端情况下，DBOS 已进入 ERROR 且存在未确认远端 intent，系统仍保留父页锁，不将它伪装成普通失败。该状态不支持直接 retry/accept；界面说明核实供应商结果后显式取消，再新建任务。

## 前端恢复与编辑一致性

任务协调器在 App 挂载，模型设置与阅读路由不改变服务器任务。首次发现任务之前即锁定服务器作品，防止刷新后的短暂空档重复提交。任务状态、页面保存状态和原有上传/再生状态相互独立，本地作品不被另一服务器作品的后台任务锁住。

任务面板提供原配置匹配、明确提供凭据、保留已有成果、计费确认后重试和取消。手机画布有「查看生成任务」入口，长面板可滚动。公开快照与作业引用采用白名单，不持久化 Key、原始供应商异常或整个请求对象。

本轮保守地在活动任务和终态同步期间锁住整份服务器作品。已提交子页在终态统一读取；多个任务的终态读取按作品串行，并持有独立签名锁。保存失败重试同样遵守任务锁，成功时只回放原工作区和该字段的最新已接受修改，保留新热点链接、评分、新输入与草稿。

## 浏览器实际检查与边界

从真实服务器作品库打开测试任务后，页面自动显示同一 `waiting_credentials`；刷新后仍显示待恢复状态，编辑保持禁用，原配置不匹配时恢复按钮禁用。随后成功进入设置并填写部分本地假供应商配置，未开启记住Key。

后续点击/输入持续遇到浏览器工具的命令超时，工具同时报告Mac处于锁屏状态。重置与重新绑定后未能完成整条按钮操作验收；没有绕过系统锁屏或改用未授权的浏览器控制方式。因此，不将后端17场景和前端136项回归等同于浏览器中的完整人工恢复流程。现有真实画面见刷新后的恢复面板（当时本机截图/评审缓存，不随仓库发布）。
