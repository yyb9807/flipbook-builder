# 根页与单页再生：真实进程故障验收

> 历史记录（2026-10-18）。本文保留当时状态；当前实现与可运行命令见[文档导航](../README.md)和[验证说明](../VERIFICATION.md)。旧 PoC / 36 场景 CLI 已退役。

2026-10-18，在本机隔离 Postgres 16 上执行。实际 Uvicorn、正式 API、正式 agents、DBOS 和数据库共同运行；仅网络模型供应商替换为本地 HTTP 假服务，没有调用付费模型。

## 实际结果

- 主套件 **32/32** 通过：原有子页 17 场景，新增根页与再生 15 场景。机器证据：[round3-durable-generation.json](evidence/round3-durable-generation.json)。
- 后追加的同提示词再生缓存验收 **1/1** 通过：连续两次同提示词再生实际调用出图服务两次，生成不同的不可变图片 URL。独立执行证据：[round3-regeneration-cache.json](evidence/round3-regeneration-cache.json)。
- 独立审查后追加的“未知远端结果＋本地图片缺失”交叉故障 **3/3** 通过：[round3-asset-unknown.json](evidence/round3-asset-unknown.json)。当时的验证器包含以上全部 36 场景；本机结果分别来自 32＋1＋3 三次执行。该旧入口现已退役。
- 验证脚本 `ruff` 和 Python 编译检查通过。此处不代表远端 CI 已执行，也不代表真实模型的质量、延迟和计费已验证。

根页图片上传在分析完成后被 `SIGKILL`，重启无需再次提供 Key 即可完成本地构图、复用上传分析热点并提交根页。已完成的视觉分析仅调用一次，没有增加一次定位调用。原文件和稳定根页 ID 均保留，同操作重放复用同一个任务。

文字根页与单页再生分别在规划后、出图后、数据库提交后被三次 `SIGKILL`。重启后需要下一阶段凭据时进入 `waiting_credentials`，显式补充后继续；已完成的分析或规划、出图、定位各调用一次。数据库提交后的重放没有创建重复节点，再生仍使用原节点 ID。

未知结果覆盖根页分析、规划、出图和定位：查询及补 Key 不触发重新调用；明确 retry 才进入第二次尝试。根页可接受已有文字，定位可接受确定图片并保留空热点。单页再生图片未知不能 accept，取消时保留原页。根页和再生的远端晚结果均在明确取消后丢弃，取消状态经重启保留。

上传资源在已完成的分析检查点后缺失时，以本地存储错误结束，不重新调用视觉分析。若远端请求仍为 started 未知结果，则同时丢失本地图片不能证明该请求没有计费：上传分析、文字根页定位和再生定位分别实测在真实请求期间 `SIGKILL`、删除对应图片、重启，均保留 `waiting_confirmation / recovery` 与作品锁，禁用 retry 和 accept；补 Key 不增加调用，核实后显式取消才释放。再生的旧页面保持原状。

测试中的再生起始页通过正常上传分析创建；为构造无热点的可再生原页，测试准备阶段仅删除该隔离项目的热点，不修改任务状态、检查点或确认决策。

## 凭据检查

主套件扫描 20 表、13,152 个字段、497 个检查点单元格、2,138 个 Base64 候选和 437 个 Postgres 原始关系文件（11,247,616 字节），以及 SQL dump、工作进程日志和图片资产，未发现假 Key；序列化负控能检出假 Key。缓存与交叉故障补充验收也各自独立扫描并通过。没有扫描整个集群 WAL，避免读取其他项目的数据。

## 复现

历史执行入口已退役。原始结果和当时的环境记录保留在本文及机器证据中；当前复测请使用[验证说明](../VERIFICATION.md)。

请替换成已安装 `backend/requirements-dev.txt` 的 Python 与自己的**测试** Postgres DSN。脚本创建随机独立数据库，成功后清理，不清空调用方提供的数据库；失败时保留数据库和日志。`--artifacts` 目录必须尚不存在。原始 Postgres 文件扫描需要测试数据库超级用户；Docker SQL dump 参数可省略。

浏览器场景使用 `--page-demo --port 8000`，同一宿主保持假供应商与正式 API 存活。临时 Key 只打印到终端并驻内存；stdin 的 `calls / fail / delay / stop` 控制仅存在于测试脚本，没有向正式应用添加调试接口。
