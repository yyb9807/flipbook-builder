## 1. 补齐真实浏览器闭环

用现有正式API、Postgres、DBOS和受控本地供应商创建可恢复任务，通过真实界面完成：打开任务 → 刷新找回 → 模型配置 → 显式提供临时凭据 → 完成并查看页面 → 预览/导出。补验未知结果的保留/重试/取消与跨设置页恢复，准确记录浏览器、截图、请求结果和供应商实际次数。禁止以隐藏store写入或HTTP替代浏览器按钮验收，不使用真实付费Key。

## 2. 扩展持久生成范围

浏览器闭环通过后，将根页分析（主题与图片）和单页再生接入同一持久基础。先冻结输入/不可变上传资产，再创建稳定operation/job；步骤只接收非秘密引用，真实供应商调用有持久intent，已完成结果可重用，未知结果暂停并要求明确决策。保留 `children-v1` 已有步骤序列，避免本轮扩展破坏同版本子页恢复。

根页尚未存在时也必须能发现/显示任务，刷新不退回无关联首页。成功时原子设置根页；取消/失败保留既有作品与创建输入。单页再生先冻结原页与父上下文，完成前保留旧内容，原子替换；已有热点/链接的页面继续使用保护规则。跨入口使用统一活动任务排他和编辑锁，避免分析、子页生成、再生互相覆盖。

## 3. 验收与交付

- 前后端现有回归保留，并覆盖三种任务的操作幂等、事件恢复、显式凭据、输入/项目身份和取消竞争。
