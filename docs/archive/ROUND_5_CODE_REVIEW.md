## 发现：图片热点改名未使人工核对声明失效（P2，已修复并关闭）

触发过程：上传图片生成页面，作者补充资料并勾选人工核对；之后在热点面板修改一个图片热点的名称。`backend/routers/nodes.py` 的 `update_hotspots` 在通用更新后，只针对 `kind=section` 的改名同步 `scene_document` 并把 `review_status` 设为 `unreviewed`。`kind=image` 的文字改名也改变读者看到的内容，但不会触发此逻辑。因此重新读取页面、预览和导出仍可显示“作者声明已人工核对”。

前端 `useBuilderActions.handleHotspotUpdate` 只更新热点，接口当前返回状态，不同步内容元数据。因此仅修服务端还不足以让当前页面立即显示正确状态。建议对任何**实际发生的热点文字改名**清除核对声明，前端同步处理；选中状态或几何调整不应误触发文字变化规则，同名重复写入也应保持原状态。相关语义是本轮计划第 5 项“内容或资料变化使原核对失效”。

## 已核对的边界

- 新知识页的标题、导读、版式、区块标题与正文使用显式归一化。数量、长度及正文最小长度有界；模型给出的 ID、目标页面、来源和人工核对声明不进入提交。
- `content_format` 冻结在新任务输入；读取没有 marker 的历史输入时走原有路径。工作流没有给旧任务无条件增加新的 DBOS step；知识页有插图时不调用图像热点定位。
- 知识区块连接由服务端创建，没有伪造的图像坐标或评分。区块及连接同事务保存，子页提交同时回填父连接和 scene，编辑保存从持久连接派生目标，拒绝跨页引用、重复连接、改目标和删除已有子页的 section 连接。
- 生成 provenance 使用冻结任务类型和实际模型配置；编辑允许补充作者资料，但拒绝新增、替换或删除服务器记录的 provenance。旧页再生保留作者资料，重置核对状态，并正确标记使用页面上下文。
- 参考链接仅接受无账号密码的绝对 HTTP(S)，后端、前端编辑、阅读和导出均有校验。阅读使用 React 文本或 `textContent`，不执行作者文本；链接添加 `noopener noreferrer`。本轮没有新增自动抓取或网页检索请求。
- 元数据读取和后端导出经过字段白名单；前端发布快照仅包含作品内容和公开模型说明，不复制 provider 配置、请求、Key 或任务记录。JSON 嵌入 HTML 时转义脚本边界。
- 插图意图进入新创建任务的身份；同操作 ID 的重放不能通过改变显式插图选项悄悄增加付费工作。正文格式错误是已知失败，不自动重试收费请求。

以上核对未发现其他明确 P1/P2。它们是代码层面的边界审查，不构成真实模型内容质量、参考资料真实性、跨版本工作流升级或多 worker 认证。

## 修复复核

集中修复后再次静态检查：服务端现在依据持久热点名称判断是否发生实际改名，对 image/section 一致清除核对状态；同名、选择及几何调整保持声明。section 改名仍同步正文标题，接口返回公开 metadata。前端增加即时失效、同一作品/工作区及同一热点最新操作的响应保护，并清除对应未保存草稿中的旧核对状态；这避免用户回到表单保存时恢复旧声明。

第一次修复复核又识别了一个并发残留：不同热点使用不同队列 key，整份 `saved.content_metadata` 回填可能接收其他热点操作之前的旧状态。例如热点 A 的几何请求先在服务器读到 `reviewed`，响应延迟；热点 B 改名后 `unreviewed` 已同步；A 迟到后满足自己的 operation guard，仍可在前端覆盖为 `reviewed`。该问题已即时反馈并纳入同一 P2 的修复。

最终复核确认：`useBuilderActions` 使用每页的本地内容修改 epoch；热点实际改名或显式内容保存时，在乐观更新及请求入队前递增/捕获，普通服务器读取不会递增。热点返回 metadata、页面保存返回 metadata/规范 scene/hotspots 时，除了原有工作区及操作保护，还要求 epoch 匹配。已接受的热点响应不再重复清除较新的人工核对声明。因此旧的几何或改名响应不能覆盖后续内容保存；旧的页面完整快照也不能覆盖后续改名。失败改名经普通 GET 替换后重试，仍能在同 epoch 接收服务端的未核对状态。已保存节点和同节点未保存草稿均在实际改名时使旧声明失效。

主任务报告的实际证据：相关前端定向回归 26 项通过，涵盖跨热点逆序、同 tick 入队、后续显式 metadata 保存、失败改名→GET→重试及旧页面快照迟到；后端全量 257 项通过。真实浏览器图片热点改名后显示未核对，刷新后仍为未核对。以上测试和浏览器由主任务执行，本审查仅静态读取对应实现及回归用例。原 P2 及其响应并发残留关闭，无其他待修复审查发现。

同时审查浏览器验收发现的离线播放器启动修复：`build-player.mjs` 为嵌套打包显式设定生产 JSX（`oxc.jsx.development=false`、关闭 refresh），使开发服务器导出的经典脚本与 production React 一致；通过 define 内联运行时环境，没有修改宿主 `process.env.NODE_ENV`。`verify-player.mjs` 在 development/production 两个隔离子进程中真实打包，通过 JSDOM 执行生成脚本、检查三层导航、来源、人工核对及无外部模块脚本，同时断言宿主环境不变。静态复核未见该修复引入新的 P1/P2。该回归不替代主任务的真实下载播放器浏览器验收。

本次复核没有运行任何测试、浏览器或检测器，没有修改生产实现；测试通过数量以主任务的实际输出为准。
