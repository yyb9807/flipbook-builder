# 第八轮计划：固定样例与模型质量评估

制定于 2026-10-19，实施前基线为 `d3dc4b5`。本轮先建立可复跑、可审查的质量评估流程，再用受控回放完成验收；不改变生产提示词、页面合约或数据库。

后续范围调整：按用户要求移除 GitHub Actions CI/CD；下文 CI 条目保留为制定时的计划，实际检查改为本地执行，结果见[实施报告](ROUND_8_IMPLEMENTATION.md)。

## 目标与范围

1. 固定 6 个中英文案例：水循环来源摘要、明确虚构的预约流程，以及同一幅原创三形状图片，各有中文与英文版本。冻结素材、来源依据、事实检查点、禁止编造的结论、分支选择和图片真值框。图片只有一个独立合成场景，不能代表自然图泛化。
2. 每个案例运行根页、子页、孙页，共 18 个生成阶段。复用实际 `InputAnalysisAgent`、`PageGenerationAgent` 的提示词、解析和规范化。图片根页使用原图分析；其后按生产行为生成知识页，不调用图片生成。子页仅收到所选父区块正文，或图片页的描述，不额外注入根素材或祖先全文。
3. 固定分支使用案例中的标签选择规则，记录实际标签、区块及上下文摘要。找不到指定分支时明确阻断后续阶段，不偷偷改选无关区块。对比运行要求同一数据集、评估方法、覆盖范围及相同实际分支路径；条件不同则标为不可直接比较。生产代码摘要变化作为明确的候选变量展示，此时不能把差异仅归因于模型。

## 评估方法

- 自动指标仅检查可验证信号：知识页结构与正文空缺、重复内容、分支引用一致性，以及图片热点一对一标签匹配、IoU、精确率、召回率和重复框。保存原始与规范化结果的差异，防止过滤坏输出后误报成功。
- 正文实质与事实、热点语义、跨页推进与一致性、指令遵循使用带锚点的 0–4 分量表。事实与禁止结论逐项对照固定依据，评审必须提供理由和输出证据。未审、漏项、来源不匹配或输出已变化时不得给出通过或总质量分。
- 分别报告执行成功、自动检查和人工质量；受控回放只证明评估程序工作，不代表真实模型质量。先保留人工基线，不接入自动模型裁判或把关键词命中当事实核验。
- 方法参考 [OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，实现保持供应商无关；无需外部评估平台。

## 运行、记录与成本边界

- 默认离线受控回放，无网络、无密钥、无数据库。独立 CLI 提供运行、评审模板、应用评审、生成静态报告和运行对比。
- 真实调用必须显式选择 live 模式、模型、供应商地址与凭据环境变量名，并设置调用次数、预留输出 token 与时间上限。程序不自动读取 `.env` 或产品保存的密钥，不自动重试。调用上限不等于金额预算，输入 token 和供应商计费仍需运行者核对；本轮验收不执行付费调用。
- 分发前原子记录调用意图并预留额度；完成阶段可以恢复，失败或结果未知的阶段不得通过自动恢复再次调用。数据集、代码、运行和评审以摘要绑定，防止混用结果。
- 本地运行目录默认忽略入库。原始响应有体积上限，凭据与错误细节脱敏；报告使用白名单字段、转义正文、离线资源和禁脚本策略。不能把真实供应商文本或密钥意外带入公开证据。

## 验收与交付

1. 数据集自检：唯一 ID、来源与事实依据、分支选择、图片摘要/尺寸/边界框以及原创素材许可。
2. 完整离线流程：6 案例、18 阶段、保存恢复、评审模板、应用评审、桌面和 390px 静态报告阅读、两次运行对比。
3. 负例：空/重复正文、错误热点、断链/分支偏离、跨页矛盾的人工判定、缺失或伪造评审、摘要变化、预算不足、未知请求、密钥泄漏哨兵。不得产生虚假通过或误导性的优胜结论。
4. 受控 HTTP 供应商验证实际传输与预算，不访问收费服务。CI 只运行离线评估及相关测试，保留既有任务、历史、发布验收。
5. 更新运行手册、文档导航、验证说明和本轮报告。独立审查发现问题后修复并复测；真实模型分数保持待测。
